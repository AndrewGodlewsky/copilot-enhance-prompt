# Privacy and storage

Enhance Prompt sends the request and permitted context to models accessed through your GitHub Copilot account. Fallback may send the payload to multiple Copilot models. AI-assisted context can also send the original request and candidate file paths to a separate selector model. It has no analytics or tracking. Copilot receives a canvas result through explicit Send or the automatic-send workflow you enable. Prompts typed directly into Copilot chat are unchanged by the plugin.

Project reads use the attached session's `workingDirectory`. Remote workspaces expose no local files. Sensitive filenames and links escaping the project are refused. Recognized secrets in automatically gathered project instructions, README/extra context, stack information, source excerpts and Git metadata/diffs are masked before trimming. File exclusions apply across automatic context routes and resolved link targets. Masking cannot identify every secret; review material before sharing.

Explicit attachments are copied into a temporary attachment directory. Registered copies older than one day are cleaned when the worker starts or another file is attached. Only completed uploads owned by the attached Copilot session may be read. Their contents can be sent to the configured models; images are recognized by bytes and their paths are included for the destination agent. Attachments, your typed request and custom instructions are not automatically secret-masked. [Complete data flow](prompt-workflow.md).

Both enhancement buttons wait for all selected attachments, including files queued for upload. Cancel excludes an uploading file; a failed upload stays visible until you remove it and either reattach it or choose to continue without it. Clear is unavailable while uploads are pending and clears failed uploads afterward. Completing an upload never starts enhancement or sending. Closing the canvas cancels pending uploads and ignores late results; only completed attachments are retained with drafts. Changing the attachment set during enhancement prevents automatic sending.

Each upload has a local receipt containing a hash of its session/installation identity, safe filename, file identity, byte count and chunk sequence. The backend supplies ownership; browser input cannot choose it. Reads and writes reject directory links, file links, hard links and file replacements, and use a verified open file handle. Completed uploads survive reopening the same session. On upgrade, only exact safe paths already retained in that session's saved drafts or parked composers are adopted. Missing or unsafe old attachments remain visible so you can reattach them.

Cleanup deletes only registered files with matching identities. Unregistered legacy files, links, changed files and unrelated folder contents are left alone instead of recursively removed. A failed interrupted write can also require manual cleanup. These checks prevent the tested path substitutions; they are not an OS sandbox against a malicious process running as your user and racing changes to parent directories or receipt files.

Local preferences, profiles, rules and history use atomic writes. The plugin uses existing Copilot authentication and does not accept provider API keys. Upgrade removes retired external profiles and encrypted API-key entries while preserving unrelated data. Inactive saved chat-hook preferences remain only for recovery; current settings and runtime paths do not read or activate them.

Project rules and new history entries retain complete canonical project paths (up to 32,768 UTF-16 code units), including meaningful whitespace in folder names. Shorter display labels do not change matching. Older rule scopes at the former 200-character cap remain visible in Rules but are not applied: re-add their text in the intended project, then remove the old rule. Older history paths at that cap stay preserved and appear under **No project recorded**, with an explanation in Project location. Their missing suffix cannot be recovered safely. Short legacy identities continue to work. If an older version already trimmed whitespace from a clipped path and saved the shorter value, the original cutoff is no longer detectable. Review older project rules manually if you used long paths with spaces near that limit.

History, context summaries and session drafts are plain text in the plugin's data directory. Since 0.12.16, session panel values use individual `data/sessions/<session-hash>.json` files; shared rules, models and history remain in `data/state.json`. The hash does not encrypt the data. See [migration and private recovery](session-storage.md). Disable Save history to stop retaining new prompt content. Delete everything removes models, rules, history and the current session's retained panel data. Attached copies are also cleared. It does not erase Copilot conversations, exported downloads or the separate usage accounting source.

**Settings → Retained storage** offers a separate, explicit inspection and limited inactive-draft cleanup. It records local PID ownership under `data/session-activity`, returns only sizes/IDs/locations, and preserves unknown or active workers, uploads and usage. No automatic draft expiry or external upload is introduced. See [exact fields, safeguards and limitations](retained-storage.md).

Since 0.2.4, background Copilot helpers retain model, timestamp, token counts, reported AI credits, availability and accounting IDs under the data directory's `usage` folder. This is local accounting for Usage Insights, with no automatic expiry or upload by the plugin. Prompt text, responses, file contents, endpoint URLs and account identities are not exported. History switches and clearing controls leave accounting intact. Close Enhance Prompt before deliberately deleting only that folder. If accounting cannot be saved, the temporary helper journal is preserved for recovery and can contain the helper's transcript. [Location and coverage](copilot-background-rewriting.md#usage-visibility).

The UI is served only on `127.0.0.1`, with an unguessable per-canvas token, exact host/origin checks, request limits and confined static-file serving. No remote scripts load. Agent-callable canvas actions cannot send prompts or grant consent. As with other local extensions, processes already running as your OS account are outside that web-origin boundary.

From 0.12.7, helpers register an owned recovery entry before input is sent. The local `usage/recovery` registry holds a session ID, temporary directory location, file identity, random ownership token and retry metadata; it contains no prompt text. A matching marker records confirmed shutdown. Recovery serializes normal cleanup and retries across processes, deduplicates existing accounting receipts, and deletes raw helper files only after durable accounting succeeds. Opening the plugin attempts at most eight stopped journals; failed retries back off from five minutes up to one hour. **Settings → Retry usage recovery** bypasses the delay for another bounded pass. No network requests or inference are used.

Live/unconfirmed helpers, changed ownership, links and malformed journals are left untouched. A crash before shutdown was confirmed needs maintainer investigation; restarting alone is not proof that an old helper stopped. Older unregistered temporary folders cannot be safely adopted automatically. Show Logs includes only recovery counts. History deletion does not remove the recovery registry or usage receipts.

**Show Logs** collects a support report only when opened. The panel and worker each keep at most 200 diagnostic events in memory, including operation names, outcomes, timestamps, durations and recognized error codes. The report also includes plugin/runtime versions and OS/architecture. It excludes prompts, model output, file contents, paths, account names, credentials and raw error messages. It is not written to disk or uploaded automatically. Restarting clears the corresponding component's buffer; copying a report places it on your clipboard for you to share.
