# What context coverage means

Context notes distinguish **complete file discovery within the permitted scope**, **partial discovery**, and **unavailable discovery**. The counts describe filename discovery, not the number of files read or total files on disk. Excluded, sensitive and binary paths remain excluded. Complete discovery does not mean the entire project is sent: the plugin selects excerpts under the existing level budget.

Git discovery uses NUL-framed filenames, preserving Unicode, tabs and newlines where the OS permits them. It keeps at most 50,000 distinct names, with a six-second/16 MB command limit. A truncated final record is discarded. The filesystem fallback keeps up to 8,000 eligible files and descends at most six levels; inaccessible directories and limits produce partial-coverage notes. An unavailable Git listing falls back to a bounded walk and says so. When discovery is partial, content search reads only individually permitted candidates rather than running a repository-wide grep with an incomplete exclusion list.

For **Relevant code, AI-assisted and AI Test**, name a project-relative path such as `src/auth/session.ts`. Use backticks or quotes around a path containing spaces. Up to twelve path candidates (240 characters each) are considered ahead of general ranking, even if ordinary enumeration did not reach them. The existing six/ten-file selection limits still apply. Explicit paths take precedence over AI choices inside that limit. Absolute paths, URLs and parent traversal are not candidates; attach outside-project material explicitly instead.

Named paths still pass file privacy, exclusion, confinement and final read checks. A candidate name is not proof a file exists: up to twelve bounded text probes verify readability before reserving snippet slots. Dotted symbols or empty/binary files cannot displace readable ranked evidence. Notes identify excluded or unreadable requested candidates without exposing their contents. Quoted/backticked paths retain their punctuation. Instruction files already included as rules are not duplicated as source excerpts. AI Test receives readable candidate names but its confined reader still verifies each final read. Files can change between these reads; a failed final read is reported rather than reused from the probe.

Keyword extraction recognizes Unicode letters, marks and identifiers; the plugin still writes English. Source text, identifiers and quoted material are preserved. Each searched file retains at most twenty hit positions: its first ten and latest ten, so a long early cluster cannot discard all later evidence. Snippets prioritize up to six separated regions before filling neighboring lines. Very long lines end with an ellipsis, and line numbers, separators and truncation markers count toward the existing 1,400/1,800-character excerpt budget. The overall 28,000/45,000-character code-context budgets remain unchanged. These are selected excerpts, not exhaustive or transactionally consistent project analysis.

`node scripts/audit/context-coverage.mjs` compares the previous production path at `190ee12` with this version over 30,001 synthetic non-Git files. It verifies an explicit target beyond the traversal cap, exclusion precedence and payload bounds without model calls. [Raw samples and source hashes](audits/v1/context-coverage-measurements.json) distinguish first/warm samples and report endpoint memory, not peaks. Historical search/enumeration timing scripts should be run from their recorded commits when reproducing exact old output comparisons; coverage and excerpt behavior intentionally changed here.
