# Enhance Prompt v1 readiness audit

**I would not call 0.12.0 ready for mass adoption yet.** Keep the preview label while fixing the demonstrated privacy, cancellation and attachment problems, strengthening release maintenance, and removing the shared-storage scaling bottleneck. The core workflow is worth keeping; the measurements do not justify removing animation, accounting, or context choices.

Audited source: `d25be463718f1b5d8ab663177fc9aa248956f762`, **0.12.0**, 16 November 2026. This work adds audit reports and offline benchmark tools only. It does not fix the findings, change product behavior, bump the product version, publish a release, or certify the plugin secure.

Follow-up work is tracked in [GitHub issue #40](https://github.com/AndrewGodlewsky/copilot-enhance-prompt/issues/40). See the [implementation plan](implementation-plan.md) and [first-batch results](first-batch-results.md) for subsequent fixes; the findings below describe the original audit baseline.

For the current state after the implementation pass, use the [release ledger](backlog-progress.md) and [remaining acceptance gates](remaining-gates.md). The historical findings below are not a list of unfixed defects in the latest preview.

## Ranked v1 checklist

“Before v1” is a release recommendation, not a CVSS rating. Concrete local preconditions matter; this report does not claim remote unauthenticated compromise or observed exploitation.

| # | Priority | Finding and consequence | Required change / acceptance |
| ---: | --- | --- | --- |
| 1 | Before v1 — security | **Git context reads can execute a configured clean/process filter.** A benign disposable filter ran during diff collection despite existing fsmonitor/textconv protections. A filter must already be configured; a normal clone does not copy `.git/config`. | Prevent effective filters from executing throughout diff collection, including name discovery, without modifying user Git configuration; otherwise skip affected collection with an explanation. Preserve legitimate diff behavior where safe. [SB-01](security-boundaries.md) |
| 2 | Before v1 — privacy | **Privacy revocation is stale during a run.** Disabling project reads during AI selection still allowed a later source read; disabling Save history during inference still retained the result. Both were reproduced. | Re-read current access/retention before each later read, model send and history write. Keep the intentional prompt-set snapshot separate from revocable privacy. Add delayed-operation/multi-canvas regressions. [SB-02](security-boundaries.md), [RS-1](runtime-security.md) |
| 3 | Before v1 — sending | **Closing/cancelling while Send checks are pending can still enqueue.** Reproduced with a stubbed session. | Propagate cancellation through the send boundary and recheck immediately before dispatch. Explain that an already accepted send cannot be recalled. [SB-03](security-boundaries.md) |
| 4 | Before v1 — attachments | **Lexical attachment paths and chunk state are insufficient.** A junction reached outside the attachment root; a later chunk could append without a registered preceding upload. Requires local path manipulation and an authenticated request, not an unrelated website. | Canonical confinement, owned upload records, chunk sequencing, per-session ownership, aggregate quotas and race-resistant file handling. Keep deliberate uploads supported. [SB-04](security-boundaries.md) |
| 5 | Before v1 — update lifecycle | **Cancellation releases update protection before helper cleanup finishes.** The updater could run while synthetic model shutdown/receipt handling remained active. Normal separate-process exclusion did work. | Reserve work until the underlying operation and cleanup settle, independently of the HTTP/UI wait. Cover model tests as well as enhancement. Reconcile interrupted updates before retry. [RS-2](runtime-security.md) |
| 6 | Before v1 — project identity | **Long paths collide in project rule scope.** Distinct 211-character paths shared a truncated key. History normalization also truncates project identities to 200 characters. | Preserve canonical identity; shorten only labels. Migrate ambiguous old scopes conservatively, never guessing another project's rules. Test long-path history grouping too. | 7 | Before v1 — fail closed | **Unknown remote/local metadata is accepted as local.** Missing/null `isRemote` passes the current truthiness check; no malformed real host response was observed. | Require an explicitly local canonical directory. | 8 | Before v1 — supply chain | **Bundled third-party notices are absent.** The original MIT license is preserved, but does not cover every redistributed library's own notice. | Generate/check notices for the actual emitted libraries and copied assets; retain original attribution. | 9 | Before v1 — release integrity | **No checked-in clean-build CI or dependency-maintenance workflow.** Committed bundles can drift from source; current check compares copies but does not itself rebuild them. | 10 | Before v1 — user/maintainer safety | **No complete security reporting, pause and recovery policy.** Public issues are the main route, and disabling metadata checks does not disable the plugin. | Publish a verified private report route, supported versions, maintainer response ownership, and disable/update/rollback instructions. Add concise in-product help linking to them. See the pause procedure below. [D3](distribution-readiness.md) |
| 11 | Before broad heavy use — storage | **All old session drafts/results grow one shared JSON file.** At 30,000 tiny session pairs, one small data write took 250 ms; redundant reads amplified work. | Partition session data, bulk-load state, coalesce saves with explicit flushes, preserve atomic transactions and recovery. Show stored-data size and offer deliberate inactive-session cleanup. No automatic deletion was approved. [Performance](performance.md#1-shared-draft-storage-highest-scale-priority) |
| 12 | Before v1 — correct inputs | **Enhance remains enabled during attachment upload.** The run snapshots only completed paths, so a visible pending upload can be omitted. | Coordinate upload completion with both Enhance entry points and automatic-send flow; test slow/failing final chunks and cancellation. [U1](distribution-readiness.md) |
| 13 | Before v1 — accounting recovery | **Failed usage flush preserves raw journals without a supported later retry.** Accounting may remain missing from the retained source, and temporary transcripts can linger. | Track owned failed journals, reconcile/deduplicate durably, expose recovery status and safe cleanup after success. Keep usage independent of history deletion. [RS-5](runtime-security.md) |
| 14 | Before v1 — bounded work | **Backend bounds are inconsistent with UI bounds.** Upload count/aggregate quotas need enforcement; history's numeric UI maximum is not a backend guarantee; sustained authenticated HTTP/upload saturation was not tested. | Enforce finite numeric/range/list/aggregate limits in the backend; bound outstanding work and test cancellation/backpressure. | 15 | High-value optimization | **Project gathering repeats enumeration and per-keyword search.** Deep gathering took about 5 seconds on 30,001 tiny files before inference. | 16 | Before v1 — accessibility/recovery polish | **Progress is visually numeric but exposed as indeterminate; Undo can outlive its backend recovery window.** Repeated item actions lack contextual accessible names. | Forward progress values, align recovery availability and make it discoverable, name controls by item, then check keyboard/screen reader/zoom in the host. Items 1–7 are code-boundary findings with differing preconditions; 8–10 and 18 are release-process gates. Fixing them is more important than cosmetic redesign. Lower-priority hypotheses—PID reuse, path-check/open races, global progress lookup ownership, and branch movement between metadata check and update—remain documented in the component reports and need targeted tests; they are not silently promoted to confirmed exploits.

## Download, execution and data exposure

At the audited baseline the tracked repository tree was **7,080,178 bytes / 305 files** uncompressed. The actual extension plus adjacent web files total **1,025,846 bytes**, about 1.03 MB. These are file sizes, not compressed network transfer or installed Git-cache allocation. This audit adds documentation/tools to the repository; the loaded application bytes remain unchanged.

Normal users receive committed JavaScript/CSS/images and plugin metadata. They do **not** install npm packages or a new SDK/runtime to use the plugin. Copilot supplies those. The backend nonetheless executes with their OS account's privileges. Four bundled backend libraries and 54 frontend JS packages remain the maintainer's update responsibility; the desktop-owned SDK/runtime/browser are the host vendor's responsibility. A `devDependencies` classification does not mean code is absent from the bundle—`proper-lockfile` is an example.

To shrink the distribution, publish a verified runtime-only artifact/subdirectory containing manifest, branding, extension/web assets and complete notices. Exclude duplicate compiled copies, development tools, tests and prototypes from that installable artifact while retaining them in the source repository. Verify marketplace provenance/update resolution against the new layout before switching. Saving roughly 6 MB of source/docs is useful packaging hygiene, but it does not reduce the backend's OS authority. Do not sacrifice accessibility libraries, locks or validation merely to reduce dependency count.

Typed text, selected context and explicit attachments go to Copilot models. Automatic context is selectively masked; typed/custom/attached text is not. Drafts, results and history are plaintext locally. Usage receipts exclude prompt/file/account text, but a failed raw helper journal can contain a transcript. Update checks send configured source/version metadata to GitHub, not project content. Support logs are bounded and user-copied, with no automatic upload. See the [data diagram](architecture.md#data-lifetime-and-recipients) and [field-level review](runtime-security.md).

Both root and web npm audits returned **zero reported known advisories** on this date. That is not a security clearance: it excludes undisclosed vulnerabilities, custom bugs, the host's dependencies and future changes. [npm describes audit scope](https://docs.npmjs.com/auditing-package-dependencies-for-security-vulnerabilities/).

## How users can pause and recover

For a credible vulnerability or suspicious behavior: stop affected use, cancel work, disable Enhance Prompt in Copilot's Installed plugin management, and restart Copilot so an already loaded backend is gone. Do not rely on merely hiding the canvas; cancellation races are findings in this report. If policy controls activation, use the indicated administrator route. The supported CLI has a separate `plugin disable` operation; verify the installed identity instead of guessing it. [GitHub plugin management reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference)

Disabling automatic update checks only stops this plugin's metadata checks. It is not a pause switch. For a normal support issue, copy Show Logs before restarting; for suspected malicious code, do not reopen it merely to collect logs. Do not post raw journals, attachments or data directories publicly. Apply the appropriate plugin or desktop fix, then verify source/version and preserved drafts. Do not use uninstall, Delete everything, credential deletion or speculative file cleanup as routine update recovery. The exact desktop disable/restart UI procedure remains an owner-run verification item. [Detailed procedure and limitations](distribution-readiness.md#disable-update-and-recovery-guidance).

## Maintainer workload

| When | Minimum responsibility |
| --- | --- |
| Every change/release | Review dependencies, clean install from both locks, typecheck/build/test/check, compare generated output, update notices/inventory and user-facing release notes. |
| Continuous alerts; weekly review | Monitor advisories for both npm roots and host/runtime releases; triage actual shipped/build-time exposure. Batch routine updates, but expedite relevant security fixes. |
| Each supported Copilot update | Inspect changed experimental contracts and run isolated integration fixtures; verify live account/policy changes separately with consent. |
| Monthly | Verify private reporting/recovery instructions, review temporary-journal failures and storage growth, check branch/release access and pending accessibility issues. |
| Security incident | Identify affected versions, offer a tested disable/mitigation path, publish safe advisory/fix information, and test recovery before telling users to re-enable. |

This is a proposed operating policy, not a response-time promise already made. Add a named owner and sustainable response targets before launch. Full guidance and the exact emitted package/license inventory are in the [distribution review](distribution-readiness.md).

## Efficiency decision

The safest first changes preserve features: partition/batch draft storage, batch repository search, and accumulate project counts once. On the synthetic workloads, one snapshot served redundant reads in **0.10 seconds versus 2.12 seconds**; one search pass took **0.66 seconds versus 2.98 seconds**; grouping 50,000 history entries took **27 ms versus 557 ms**. The first comparison has one sample and the last exceeds the intended history range; all are operation-level prototypes, not production speedups.

I would keep the current functionality while making those changes. Do not delete usage for speed or remove the approved animation based on its small measured simulation cost. Potentially expensive feature choices are AI-assisted/AI Test inference, highest reasoning for Low effort, and any future unlimited prompt archive. Their quality/cost trade-offs require a separate decision and measured live evaluation; this audit made no model calls. [Complete trade-off table](performance.md#functionality-trade-offs-worth-a-decision).

## Verification and remaining gates

The maintained full-suite/build results are recorded in [verification](verification.md). Additional independent work reproduced the eight boundary/privacy/identity/lifetime cases across the two security reports, checked ordinary separate-process update exclusion, rendered UI components statically, audited both dependency trees, and ran all six synthetic scale workloads. A fixture passing because it reproduced a bug is not evidence that the bug is fixed. Some existing Windows file-symlink checks return early when privilege is unavailable; junction coverage succeeded.

Read coverage spans production context modules, transport/session/server, worker/model orchestration, storage/usage/updates, rules/prompts/effort, panel state/actions, every web entry/component wrapper, package/build/update sources and current user/privacy documentation. Component reports list their exact inventories. Generated duplicates are checked by rebuild/comparison, not treated as separate hand-audited programs. The review did not audit every line of every third-party package or the Copilot application itself.

Still required: owner-run narrow/wide and large-text visuals, keyboard/screen-reader/zoom, fresh marketplace install and real update/restart, actual account/enterprise-policy combinations, model output/downstream correctness, long-running multi-canvas soak, large tracked repos/diffs/images, power-loss recovery and non-Windows behavior if support is expanded. No paid models, owner's live installation changes or UI automation were used here.

Recommended sequence: **fix security/lifecycle and input correctness → add recovery/release hygiene → optimize storage/scans without feature removal → run the owner acceptance matrix → decide v1 scope and stable distribution.** The current evidence supports that plan; it does not support calling this preview production-ready today.
